# idleboxed

Локальные интеграционные сборки Idle: один закреплённый состав компонентов,
комплекты для выбранных платформ и публикация в GitHub Releases через `gh`.
Python-пакет и команда называются **iboxed**.

## Подготовка

Нужны Linux x86-64, Python 3.12+, `uv`, Git, GitHub CLI и инструменты сборки
[iroll](https://github.com/idleboxed/iroll/blob/main/docs/rollout.md).
Для RK3032 заранее подготовьте [SDK](https://github.com/idleboxed/iroll/blob/main/docs/sdk.md)
в `in/sdk/rk3032`. SDK, NOR и vendor-библиотеки
в выпуски не входят. Подготовка SDK не является частью `iboxed build`.

```bash
git clone --recurse-submodules https://github.com/idleboxed/idleboxed.git
cd idleboxed
uv tool install --force -e .
iboxed --help
```

Для уже клонированного репозитория: `git submodule update --init`.
Редактируемая установка требует сохранить исходники на месте.

## Сборка

Отредактируйте [config.toml](config.toml), зафиксируйте изменения в Git и запускайте
команду из каталога интеграционного репозитория:

```bash
iboxed build
```

`version` — номер **всего комплекта**, независимо от версий приложений.
`[[platforms]]` задаёт матрицу: по умолчанию RK3032 `standard`/`diag` и Linux x86-64
`standard`. `standard` отключает пассивную диагностику iman; `diag` включает
штатный диагностический набор iroll, но не активные аппаратные пробы.
Для ПК отдельного диагностического профиля в iroll нет.

SDK, загрузки, результаты компиляции и отчёты используют стандартные каталоги
iroll: `in/sdk/rk3032`, `in/downloads`, `tmp/`, `logs/`. Параметры iroll
в конфиге бандла не дублируются. Снимок исходников и чистое назначение находятся
в системном временном каталоге (`TMPDIR`); готовые архивы — в `out/<version>/`.
Сборщик вызывает iroll из выбранного снимка, не глобально установленную версию.
Проверки источников, SDK, ELF и выкладки остаются в iroll; второй реестр рецептов
и ядер здесь не заводится.

### Закреплённый состав и свежие ветки

Обычная сборка использует gitlinks `components/` из коммита интеграционного
репозитория. Исходники и сабмодули должны быть чистыми и совпадать с этими pins.

```bash
iboxed build --latest
```

`--latest` сначала разрешает `main` **iroll, iman, IGUI и imanlib** в конкретные SHA,
потом использует один снимок для всей матрицы. Рабочие сабмодули и закреплённые
gitlinks не передвигаются. Сторонние RetroArch и ядра остаются закреплёнными
рецептами выбранного iroll, а не обновляются до произвольных веток upstream.

Сабмодуль imanlib не заменяет Git-зависимость в Cargo.toml/Cargo.lock iman и IGUI.
Манифест отдельно сохраняет checkout-коммит и реальные Cargo pins;
для обновления используемой библиотеки сначала обновите зависимости самих приложений.
Снимок фиксирует источники, но не обещает побайтово одинаковые бинарники:
сборки приложений содержат дату, а результат зависит и от инструментов ПК.

### Результат

Все цели должны успешно собраться; только после этого появляется `out/0.1.0/`:

```text
iboxed-0.1.0-rk3032-standard.tar.gz
iboxed-0.1.0-rk3032-diag.tar.gz
iboxed-0.1.0-linux-x86_64-standard.tar.gz
release.json
THIRD_PARTY.txt
```

Состав зависит от выбранной матрицы. В архивах — `system/`, инструкция,
короткий `THIRD_PARTY.txt` и пустые каталоги сохранений. Пользовательские игры,
BIOS, каталог, предпочтения и сохранения не включаются. Нет `releases/`,
`licenses/`, SD-инвентаря, lock-файлов, SHA256SUMS и хешей архивов.
Версии, коммиты, используемые pins imanlib и состав пакетов перечислены в `release.json`.
`THIRD_PARTY.txt` содержит названия компонентов, лицензии и ссылки на исходники,
а не полные тексты лицензий; это справочник, не заявление о полноте юридического аудита.
Отдельные архивы исходников не формируются.

Трамплин в комплект не входит. Для входа из штатного меню отдельно используйте
[itrampoline](https://github.com/idleboxed/itrampoline/blob/main/docs/usage.md):
он собирает core и helper, устанавливает `.so` под именем выбранного штатного
ядра, создаёт запускатель и добавляет пункт в исходную `game/games.db`.
Сабмодуль `components/itrampoline` оставлен для работы с этой отдельной утилитой;
`iboxed build`, включая `--latest`, его не собирает и не обновляет.

Сборщик работает только с временным каталогом ПК: SD/NOR не открывает,
приложения и vendor ELF не запускает. Распаковку на карту выполняет владелец
после остановки приложений; корректно размонтируйте карту после записи.
Обновление существующего `system/` распаковкой не атомарно и не удаляет старые файлы.
Комплект не является образом ОС и не гарантирует устойчивость SD к отключению питания.

## Публикация

Авторизуйтесь в `gh` с правом создания Releases и запускайте отдельно:

```bash
iboxed publish
```

Команда проверяет готовый комплект и неизменность интеграционного коммита,
определяет репозиторий публикации по Git `origin`,
создаёт неизменяемый тег `v0.1.0`, затем draft Release, загружает все assets
и сверяет их имена и размеры перед публикацией. Для `--latest`-сборки выпуск
помечается prerelease. Архивы не перезаписываются через `--clobber`.

Для каждого нового выпуска выбирайте новую `version` в конфиге.
Уже опубликованный выпуск и существующий каталог результата не заменяются.
При ошибке загрузки draft остаётся для осмотра: частично загруженные assets
автоматически не заменяются. Осмотрите draft и удалите его вручную либо выберите
новую версию. Тег с другим коммитом никогда не передвигается.
Отчёты iroll остаются в `logs/`. После сбоя публикации осмотрите draft;
автоматического повтора и перезаписи assets нет.
